# Metro Voice — спецификация v0.1

> Приложение-навигатор по метро «для ушей»: объявляет в наушники текущую и следующую станцию, работает без интернета и без GPS под землёй.

Статус: черновик спецификации, до прототипа. Город по умолчанию — Москва.

---

## 0. Главная поправка к исходной идее

**«Цепляться за геопозицию» под землёй не получится.** GNSS (Global Navigation Satellite System — GPS/ГЛОНАСС/Galileo) в тоннелях не принимается вообще. Интернет на станции тоже ничего не даёт для позиции — карта и так будет офлайн.

Поэтому позиция в метро — это **вывод, а не измерение**. Мы знаем граф линии (порядок станций, время перегонов) и по датчикам телефона видим ритм поезда: *стоит → разгоняется → едет → тормозит → стоит*. Задача сводится к тому, чтобы «наложить» этот ритм на граф. Формально это HMM (Hidden Markov Model — скрытая марковская модель): скрытое состояние — «где поезд на графе», наблюдения — события датчиков.

Твоя мысль «направление определим на следующей станции» — правильная, но это частный случай общего принципа: **держим несколько гипотез одновременно и схлопываем их, когда приходит различающее наблюдение.**

Второй принцип: **ошибочное объявление хуже молчания.** Голос говорит уверенно только при вероятности гипотезы выше порога; иначе — осторожная формулировка или тишина.

## 1. Проблема и пользователь

| | |
|---|---|
| Кто | Пассажир в наушниках (музыка, подкаст, ANC (Active Noise Cancellation — активное шумоподавление)), не слышит объявлений поезда |
| Боль | Не на всех станциях и не во всех вагонах есть видимые табло; пропуск станции, нервное «где я» |
| Работа продукта | Сказать в ухо: «Станция X. Следующая — Y» и показать то же на экране блокировки |
| Вторичные сегменты | Слабослышащие (визуальный канал), туристы (английский), незрячие (уже слышат вагон, но могут хотеть дублирование и навигацию по пересадкам) |

**Вне рамок v1:** построение маршрутов (это делают Яндекс Метро и др.), наземный транспорт, МЦД/электрички.

## 2. Источники сигнала

| Сигнал | Android | iOS | Под землёй | Что даёт |
|---|---|---|---|---|
| GNSS | ✅ | ✅ | ❌ | Якорь: станция входа (последний фикс у вестибюля), открытые участки линий |
| Акселерометр | ✅ | ✅ (в фоне — с оговорками, §6) | ✅ | Фазы движения → счёт перегонов, длительность перегона |
| Магнитометр | ✅ | ✅ | ✅ | Детекция остановок по магнитному полю тяговых двигателей; «отпечатки» перегонов |
| Барометр | ✅ (не на всех моделях) | ✅ (CMAltimeter) | ✅ | Скачки давления от поршневого эффекта в тоннеле, профиль глубины станций |
| Cell ID (идентификатор базовой станции сотовой сети) | ✅ `TelephonyManager.getAllCellInfo()` | ❌ публичного API нет | ✅ (если есть покрытие, интернет не нужен — это радио, не данные) | Абсолютный якорь после того, как собрана база «соты → станция» |
| Wi-Fi BSSID (MAC-адрес точки доступа) | ✅ скан, но с троттлингом системы | ❌ скан недоступен | ✅ на станциях | Абсолютный якорь на станции |
| Расписание / время перегонов | данные | данные | ✅ | Ожидаемая длительность каждого перегона → различение гипотез |
| Ввод пользователя | ✅ | ✅ | ✅ | «Еду до станции Z» — снимает неоднозначность направления сразу |

Вывод: **Android объективно сильнее** (Cell ID + Wi-Fi дают абсолютные якоря). На iOS остаются только движение + время + GPS у входа.

### Что известно из исследований

- **SubwayPS** — детекция движения поезда по дисперсии акселерометра по трём осям, применимо к большинству метрополитенов без инфраструктуры.
- **London Underground, акселерометр + база «отпечатков»** — заявлено 100% точности линии и станции после ≥4 перегонов подряд.
- **M-Loc** — акселерометр + барометр для детекции остановок, магнитометр + барометр для отпечатков перегонов: 93% точности на 3 станциях, 98% на 5 (3 линии, 55 станций).
- **Lee & Han, Сеул** — детекция остановок по магнитометру >90%.

Практический смысл: **детекция «стоим/едем» — решённая задача. Нерешённое — кто я на графе в первые 1–2 перегона.** Именно там нужны якоря и ввод пользователя.

## 3. Алгоритм (ядро)

### 3.1 Модель состояния

```
State = (line, position, direction, phase)
  position  ∈ {station_i, segment_i→i+1}
  direction ∈ {+1, −1}
  phase     ∈ {STOPPED, ACCEL, CRUISE, BRAKE, WALKING}
```

Распределение вероятностей по состояниям обновляется forward-фильтром HMM на каждом событии.

### 3.2 Конвейер

```
датчики (50 Гц) → классификатор фаз движения → события
   StopStart / StopEnd(duration) / Departure / Walking / AbsoluteFix(station, confidence)
→ фильтр по графу → гипотезы с вероятностями
→ политика объявлений (порог уверенности) → аудио + UI
```

Классификатор фаз v1 — правила на признаках (дисперсия ускорения, модуль магнитного поля, производная давления), v2 — небольшая модель на собранных данных.

### 3.3 Старт поездки

1. Пользователь включает «поездку» (или приложение предлагает сам — когда GPS показывает вход в вестибюль и следом пропадает фикс).
2. Последний GPS-фикс → ближайшая станция (или 2–3 кандидата, если вестибюли рядом / пересадочный узел).
3. Направление неизвестно → две гипотезы по 50%.

### 3.4 Разрешение направления (по убыванию силы)

1. **Ввод пользователя** — «еду до Z» или тап «в сторону X». Мгновенно.
2. **Абсолютный якорь на следующей станции** — Cell ID / Wi-Fi (Android).
3. **Длительность первого перегона** — если перегоны в обе стороны различаются по времени заметно (порог подбирается на данных, ориентир ~20%).
4. **Открытый участок с GPS**, если линия выходит на поверхность.
5. **Последовательность из нескольких перегонов** — комбинация длительностей уникальна гораздо чаще, чем одна.

Пока направление не разрешено, голос говорит: «Станция A. Направление уточню на следующей» — без вранья.

### 3.5 Подводные камни

| Ситуация | Риск | Контрмера |
|---|---|---|
| Остановка в тоннеле | Ложное «станция» | Стоп случился сильно раньше ожидаемого времени перегона → это тоннель; отсутствует барометрический/магнитный профиль станции |
| Проезд станции без остановки | Сдвиг на одну станцию | Перегон вдвое длиннее ожидаемого → гипотеза «пропуск» |
| Телефон достали из кармана / тряска | Ложные фазы | Гироскоп: отделять вращение телефона от продольного ускорения поезда |
| Пересадка | Новая линия, направление снова неизвестно | Детектор ходьбы (step counter) → граф пересадок со временем перехода → новая линия, снова две гипотезы |
| Кольцевая линия | Направления «по/против часовой» | То же, что обычное направление |
| Вилочное движение / разветвления | Граф не линейный | Граф поддерживает ветвления с самого начала |
| Пользователь не в поезде, а просто стоит на станции | Ложная «поездка» | Нет фаз движения дольше N минут → пауза |

Любой абсолютный фикс (GPS, Cell ID, Wi-Fi) **схлопывает распределение** — это механизм самовосстановления после ошибок.

## 4. Аудио

### 4.1 Сценарий объявлений

| Момент | Фраза (RU) | EN |
|---|---|---|
| Отправление (детект разгона) | «Следующая — Y» | "Next stop: Y" |
| Торможение перед станцией (по ожидаемому времени + детект торможения) | «Подъезжаем к Y» (опционально) | "Arriving at Y" |
| Остановка | «Станция Y. Переход на линию L» | "Y. Change for line L" |
| Режим цели | «Ваша — через одну», «Выходим на следующей» | "Your stop is next" |
| Неуверенность | «Станция A. Направление уточню на следующей» | "A. Confirming direction at the next stop" |

Настройки частоты: *каждая станция* / *только отправление* / *только у цели*.

### 4.2 Поверх музыки

- Android: AudioFocus `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` — музыка приглушается, не ставится на паузу.
- iOS: `AVAudioSession` категория `.playback` с опцией `.duckOthers`, после фразы — деактивация сессии с `notifyOthersOnDeactivation`.
- Короткий «earcon» (звуковой маркер) перед фразой, чтобы мозг переключил внимание до названия станции.

### 4.3 Голос

- **Основной: предгенерированные аудиофайлы** каждой станции на каждом языке, входят в пакет города. Плюсы: офлайн, одинаковое качество, **правильные ударения** — системный TTS (Text-to-Speech — синтез речи) регулярно ломает ударения в названиях вроде «Марьина Роща» или «Тёплый Стан».
- Fallback: системный TTS (Android `TextToSpeech`, iOS `AVSpeechSynthesizer`) — для новых станций до обновления пакета.
- Английские названия — официальная транслитерация метрополитена, не машинная.
- v1: RU, EN. Архитектура: язык = набор аудиофайлов + шаблоны фраз, добавляется без релиза приложения.

## 5. Визуал

- **Не карта всего метро, а лента текущей линии**: вертикальная полоса станций, точка-поезд, интерполяция между станциями по ожидаемому времени, индикатор уверенности (сплошная/пунктирная точка).
- Экран блокировки: Android — постоянное уведомление foreground service с текущей/следующей станцией; iOS — Live Activity + Dynamic Island.
- Крупный шрифт, контраст, совместимость с TalkBack / VoiceOver.
- Ручная коррекция: тап по станции на ленте = «я здесь» (это ещё и разметка для обучения).

## 6. Платформенные ограничения (главный технический риск)

### Android

- Фоновая работа: foreground service с типом `location` (обязателен для Android 14+), разрешение `FOREGROUND_SERVICE_LOCATION`, нужна выданная runtime-пермиссия на геолокацию и включённые службы геолокации.
- Сенсоры в foreground service работают стабильно; использовать batching (накопление сэмплов в сенсорном хабе) для экономии батареи.
- OEM-«убийцы» фона (Xiaomi, Huawei, Samsung) — онбординг с инструкцией по исключению из оптимизации батареи.
- Wi-Fi скан ограничен системным троттлингом — использовать как редкий якорь, не как поток.

### iOS

- **Нет Cell ID и Wi-Fi скана** → только движение, время, GPS.
- Живые колбэки Core Motion в фоне приходят, только пока приложение не приостановлено. Практически это держится на фоновом режиме `location` (активная сессия Core Location). Использование location *только* как «держателя» — риск отказа в App Review; у нас есть законное основание (якорение по GPS у входа и на открытых участках), его надо явно описать.
- Фоновый режим `audio` без реального звука — отказ в ревью. Тихий трек не вариант.
- `CMSensorRecorder` пишет акселерометр даже у выгруженного приложения, но отдаёт данные постфактум — годится для сбора датасета, не для живых объявлений.
- **Это нужно проверить прототипом в первую очередь**: держит ли iOS приложение живым 40 минут под землёй без GPS-фикса.

### Батарея

Цель: ≤5% заряда в час поездки. Сенсоры вне поездки выключены; поездка стартует явно или по детекту входа.

```
city/
  graph.json        # линии, станции, перегоны, пересадки, ветвления

  audio/ru/*.opus   # названия станций
  audio/en/*.opus
  phrases.json      # шаблоны фраз по языкам
```

## 8. Стек (рекомендация)

- **Ядро (граф, фильтр, политика объявлений) — Kotlin Multiplatform**: один код логики для Android и iOS, тестируется на записанных трассах.
- **Оболочки — нативные**: Jetpack Compose (Android), SwiftUI (iOS). Причина: всё ценное здесь — фоновые сенсоры, аудиофокус, Live Activity — живёт в нативных API. Flutter / React Native добавят слой плагинов ровно там, где больнее всего.
- **Android first**: больше сигналов, мягче фоновые ограничения, быстрее итерации.

## 9. План

| Фаза | Что | Критерий выхода |
|---|---|---|
| **0. Логгер** | Приложение-самописец: пишет акселерометр, гироскоп, магнитометр, барометр, Cell ID, BSSID; тап «я на станции X» = эталонная разметка | 20–30 размеченных поездок по 3+ линиям |
| **1. Офлайн-ядро** | Классификатор фаз + HMM-фильтр, прогоняемый по записанным трассам | ≥95% верных станций после разрешения направления, 0 ложных «станций» на тоннельных стопах в датасете |
| **2. MVP Android** | Режим «еду до Z», объявления RU/EN поверх музыки, лента линии, уведомление | Живые поездки: ≥95% верных объявлений, задержка ≤5 с от остановки |
| **3. Авто-режим** | Без указания цели, пересадки, якоря Cell ID / Wi-Fi | — |
| **4. iOS** | Порт оболочки, Live Activity | Подтверждена фоновая живучесть |
| **5. Масштаб** | Краудсорс отпечатков, другие города, часы | — |

**Фаза 0 — самая недооценённая и самая важная.** Без размеченных трасс любой алгоритм — гадание; с ними фильтр отлаживается на ноутбуке без спусков в метро.

## 10. Метрики

- **Точность объявления** — доля верно названных станций.
- **Частота ложных объявлений** — главная метрика вреда; цель → 0.
- **Задержка** — секунды от фактической остановки до фразы.
- **Время до разрешения направления** — в перегонах.
- **Расход батареи** — % в час поездки.
